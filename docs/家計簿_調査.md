# 家計簿タブ 調査（2026-10-11）

> **方針変更：有料プランは使わないため Moneytree CSV は不採用。PDF 取り込み＋Apple Pay 自動記録＋手入力**
> （下の「1. Moneytree」は経緯として残す。取り込みの対象は末尾の「十六銀行の入出金明細 PDF」の節）

家計簿タブの「取り込み」に使う2つの経路（Moneytree の CSV、Apple Pay の「取引」オートメーション）を調べた結果。
各項目に **確認済み** / **未確認** を付けた。未確認のものは、実際にファイルや実機で確かめてから実装する。

## 1. Moneytree の明細を CSV で書き出す

### 1-1. どのプランで使えるか

| 対象 | CSV 書き出し | 根拠 | 状態 |
|---|---|---|---|
| Moneytree（無料） | できない | 公式ヘルプが「Moneytree Work か Moneytree Corporate を契約していれば」書き出せる、と案内。Grow の告知でも「データ出力」は有料機能として紹介 | 確認済み（無料版にない、という書き方は推定。明言する公式文は見つからず） |
| **Moneytree Grow**（個人向け有料） | できる | 「過去1年間の利用明細をCSV/Excel形式で出力し、ダウンロードまたは共有できます（最長過去2年分）」 | 確認済み |
| Moneytree Work（経費精算、有料） | できる | 「過去の利用明細はすべてCSV・Excel形式で出力可能」 | 確認済み |
| Moneytree Business（法人向け Web） | できる | 「取引データを出力」ボタン。期間・入出金の種別・口座・カテゴリを選べる | 確認済み（個人には関係しない） |

- Grow の価格（公式ページ、2026-10 時点）：Web 決済は月額 390 円／年額 3,900 円、アプリ内課金は月額 430 円／年額 4,300 円。初月は無料。
- 「日和」の利用者は **Grow（または Work）に入っている人** が前提。入っていない人向けに「手入力」と「Apple Pay」の経路を残す。

### 1-2. 書き出し手順

**iPhone（公式ヘルプ・英語版の手順を訳したもの）**

1. 「残高」カード（Balances Card）で、書き出したい金融サービスをタップする
   - 全口座をまとめて書き出すときは、虫めがね（検索）画面から始める
2. 口座（カード）をタップする
3. 右上の **ダウンロード** アイコンをタップする
4. 期間を決める（または「すべての取引」）
5. 形式で **CSV** を選び「ダウンロード」
6. 共有シートが出るので、「"ファイル"に保存」や AirDrop・メールで渡す

- 状態：手順の流れは **確認済み**（公式ヘルプ）。日本語版アプリの **ボタンの文言は未確認**（日本語版ヘルプの該当ページは取得できなかった）。
- クレジットカード・電子マネー・現金記録の明細も書き出せる（公式ヘルプ）。

**Web（app.getmoneytree.com）**

- 「Personal（個人）> 銀行（またはクレジットカード）> 口座名（カード名）」を開くと、右上に **Export（書き出し）** ボタンがある（公式ヘルプ・英語版）。
- 状態：英語版の記述は **確認済み**。日本語 UI の文言は **未確認**。Grow の公式ページに「Android版、Web版には一部未搭載機能あり」とあり、Web で Grow の書き出しが使えるかは **未確認**。

### 1-3. 制限

| 項目 | 内容 | 状態 |
|---|---|---|
| 期間 | Grow：過去1年分（最長過去2年分）。2019年の告知では「前年1月1日から出力日まで」 | 確認済み |
| 中身 | 支出だけではなく、入金・出金の両方が入る（金額の符号で区別） | 確認済み（利用者ブログのコードで、金額が 0 以上を収入・未満を支出として扱っている） |
| 二重計上 | 「カード返済」「振替」カテゴリが入るので、そのまま足すとカード払いが二重になる | 確認済み（同ブログ） |
| ファイル名 | 全口座を書き出すと「全ての口座-開始日-終了日.csv」の形（例：`全ての口座-2022-01-01-2023-09-05.csv`） | 確認済み（同ブログのコード） |

### 1-4. CSV の形式

公式ヘルプには **列名・文字コードの記載がない**。分かったのは利用者ブログ（Python で集計）のコードから読み取れる範囲だけ。

| 項目 | 分かったこと | 状態 |
|---|---|---|
| 列名 | `日付`、`金額`、`カテゴリ`、`メモ` は必ずある | 確認済み（ブログのコードで使用） |
| 列の順序 | 不明 | **未確認** |
| その他の列 | 口座名・金融機関名、明細の説明（店名にあたる文字）、大カテゴリ／小カテゴリ が入っている可能性が高い | **未確認** |
| 文字コード | ブログでは `pd.read_csv(path)`（指定なし＝UTF-8）で読めているので、UTF-8 の可能性が高い。BOM の有無は不明 | **未確認**（推定） |
| 日付の形式 | `pd.to_datetime` で読めている。`YYYY/MM/DD` か `YYYY-MM-DD` のどちらか | **未確認** |
| 金額の符号 | 支出がマイナス、収入がプラス | 確認済み（ブログのコード） |
| カテゴリ | Moneytree のカテゴリ名がそのまま日本語で入る（例：「カード返済」「振替」） | 確認済み |
| メモ | 明細の文字（例：「ペイペイ」を含む行がある）が入る。利用者が付けたメモか、明細の説明かは不明 | **未確認** |

**実装の方針（推定に頼らないために）**

- 1行目を見出しとして読み、列名で探す（順序に頼らない）。
- 文字コードは UTF-8（BOM あり・なし）を先に試し、だめなら Shift_JIS で読む。
- 日付は `/` と `-` の両方を受け付ける。
- 「カード返済」「振替」は既定で取り込まない（設定で変えられる）。
- 重複は「日付＋金額＋説明（またはメモ）」で判定する。
- **最初に、本物の書き出しファイルの見出し行だけを確認する**（個人の明細の中身はリポジトリに入れない）。

## 2. ショートカットの「取引」オートメーション（Apple Pay／ウォレット）

| 項目 | 内容 | 状態 |
|---|---|---|
| 登場 | iOS 17 / iPadOS 17 で追加 | 確認済み |
| 日本で使えるか | Apple の日本語サポートに「取引作動機能」のページがある。オプションは「タップしたとき」（ウォレットのカードを選び、タップされるたびに実行） | 確認済み（機能があること） |
| 受け取れる情報 | ショートカットの入力として「取引」が渡り、**カード（またはパス）・加盟店・金額** を取り出せる | 確認済み（海外の解説記事。英語環境） |
| 絞り込み | カード、支払いのカテゴリ、加盟店で絞れる。決済・交通・入場・身分証のパスに対応 | 確認済み（同） |
| 確認なしで実行 | 「すぐに実行」を選べる（確認なしでバックグラウンド実行） | 確認済み（同） |
| 日本の iD／QUICPay／Suica で金額・加盟店が取れるか | 不明。日本の FeliCa 決済で金額や店名が空になる・遅れて届く可能性がある | **未確認**（実機で要確認） |
| 日本語 UI での項目名 | 「加盟店」「金額」「カード」などの表示名 | **未確認** |
| 不具合の報告 | Apple Developer Forums に「取引」トリガーがタイムアウトする報告がある | 確認済み（報告があること） |

**日和への送り方（案）**：オートメーションの中で「URL を開く」か App Intents（日和側に「支出を記録」アクションを用意）で、金額・加盟店・カード名を日和に渡す。金額が空のときは日和側で「金額を入れてください」の通知を出す。

### 2. 手順とボタンの文言（じゅうろくダイレクト）

公式ヘルプ「入出金明細」に書かれている範囲：

1. ログイン後、口座を選んで「入出金明細」を開く。最初は **最近30日間分**（「前月初から本日分まで」）が出る — 確認済み
2. 照会条件を変えて「**照会**」ボタンで表示を更新する — 確認済み
3. もっと前を見るときは「**更に過去の明細へ**」ボタン — 確認済み
4. 「**明細ダウンロード**」で **CSV 形式** をダウンロードできる。条件は照会画面で選んだものがそのまま入る — 確認済み
5. PDF として保存するボタン・メニューの名前 — **未確認**

iPhone で PDF にする一般的な方法（Apple 公式ヘルプ。十六銀行の画面でこの通りにできるかは **未確認**）：

- Safari で表示中のページ：共有 →「マークアップ」→「完了」→ 保存先を選ぶ（ページを PDF として保存）

### 4. 入出金明細 PDF の列（推定）

公式の資料に列の説明はない。銀行の入出金明細として一般的な形から推定した。**すべて未確認**。

| 列（推定） | 日和での扱い |
|---|---|
| 日付（取引日。和暦か西暦か、`YYYY/MM/DD` か `MM/DD` かも不明） | 日付 |
| 摘要（「カード」「振込」「振替」、引落先の名前など） | 内容。カード引落・振替の判定にも使う |
| お引出し（出金）の金額 | 支出 |
| お預入れ（入金）の金額 | 収入 |
| 残高 | 読むが保存しない。読み取りの検算に使う（前の行の残高 ± 金額 ＝ この行の残高） |
| 備考・取扱店など | あれば内容に足す |

**実装の方針**

- PDF のテキストを PDFKit で取り出し、見出し行（「日付」「摘要」「出金／お引出し」「入金／お預入れ」「残高」のどれか）を探して列の位置を決める。
- テキストが取れない（画像だけの PDF）ときは、Vision の文字認識に切り替えるか、「手入力」へ案内する。
- 残高の検算が合わない行には「読み取りが怪しい」印を付け、確認画面で直せるようにする。
- 摘要に「カード」「振替」などを含む行は既定で入れない（切り替えで入れられる）。
- 重複は「日付＋金額＋摘要」で判定する。
- **最初に、本物の PDF を1枚だけ手元で見て、見出し行と日付の形式を確かめる**（明細の中身はリポジトリに入れない）。
- 公式に CSV ダウンロード（無料）があるので、PDF の読み取りが不安定なときのために CSV も受け付けられるようにしておく。
